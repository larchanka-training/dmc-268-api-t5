# Рабочий процесс команды (git / MR)

## Ветки

- Основная ветка — `main`. Прямые коммиты в `main` не делаются.
- Каждая задача — отдельная ветка от актуального `main`:

```bash
git checkout main && git pull
git checkout -b feat/validate-checks   # шаблон: <type>/<краткое-описание>
```

## Коммиты

Используй Conventional Commits:

```
feat: добавить правило валидации JIRA-ключа
fix: корректная обработка пустого описания
refactor: вынести проверку в отдельный модуль
test: тесты для валидатора
```

Заголовок — повелительное наклонение, до ~50 символов. Тело коммита — по необходимости (что и почему).

```bash
git add <файлы>            # адресно, не git add -A вслепую
git commit -m "feat: <сообщение>"
```

## Merge request

Когда ветка готова:

1. Синхронизируй с `main`: `git checkout main && git pull && git checkout - && git merge main`.
2. Пуш ветки: `git push -u origin <branch>`.
3. Создай MR в `main` через gitlab MCP (`mcp__plugin_gitlab_gitlab__create_merge_request`).
4. В описании MR: задача, суть изменений, что проверял, какие тесты гонял.

## Правила

- Не пуши в чужие ветки; ветка = одна задача.
- Перед MR убедись, что локально зелёные тесты (см. `skills/test/SKILL.md`) и код соответствует стандартам.
- Каждое правило валидации MR должно быть описано в MR — ревьюер должен понимать, что и зачем меняется.
