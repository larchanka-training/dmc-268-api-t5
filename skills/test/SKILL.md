# Тестирование

Тесты пишутся на `pytest` + FastAPI `TestClient`. Стейдж — `tests/`.

## Первичная настройка

Зависимости для тестов (добавь в `requirements.txt` или dev-зависимости):

```bash
pip install pytest httpx
```

Файлы тестов — `tests/test_<module>.py`. Пример smoke-теста эндпоинтов:

```python
from fastapi.testclient import TestClient
from main import app

client = TestClient(app)


def test_health():
    resp = client.get("/health")
    assert resp.status_code == 200
    assert resp.json() == {"status": "ok"}
```

## Запуск

```bash
python -m pytest                          # весь набор
python -m pytest tests/test_main.py -v    # конкретный файл подробно
python -m pytest -k health                # фильтр по имени теста
```

## Как писать тесты для этого сервиса

- **Корректность валидации MR** — золотые кейсы: сценарий, проходящий валидацию, + сценарии, ломающие каждое правило.
- **Граничные значения** — пустые/длинные поля, `None`, неожиданные типы.
- **Ошибки** — проверяй код ответа и тело ошибки, а не только факт 4xx/5xx.
- **Отсутствие побочных эффектов** — валидация не должна менять внешнее состояние без явной причины.

## Правила

- Один логический кейс — один тест, имя описывает ожидаемое поведение.
- Не мокай то, что можно проверить интеграционно; моки — только для внешних границ (сеть, БД).
- При изменении логики валидации сначала пиши/правь тест под новое поведение.
