# Чек-лист код-ревью (соглашение)

Применяется при ревью любого PR в этом репозитории. Скилл `review` ссылается на этот документ как на критерии проверки.

## Корректность

- Логика валидации: каждое правило покрыто сценариями успеха и провала; поведение корректно на граничных значениях (пустые поля, `None`, неожиданные типы).
- Обработка ошибок: входные данные валидируются на границе (Pydantic-схемы), ошибки возвращают осмысленные сообщения, а не голый 500.
- Порядок выполнения проверок детерминирован и задокументирован, если порядок важен.

## Безопасность

- Нет инъекций (SQL, shell, шаблоны) — ориентир OWASP Top 10.
- Нет захардкоженных секретов/токенов; конфиденциальные данные не попадают в логи и ответы.
- Валидация не выполняет опасных действий от имени пользователя (авто-апрув/мерж) без явного согласования.

## Тесты

- Для изменённой логики есть тесты; критерии — в [testing-conventions.md](testing-conventions.md).
- Тесты проверяют поведение, а не детали реализации.

## Стиль и чистота

- PEP 8, аннотации типов на публичных функциях.
- Нет мёртвого кода, закомментированных блоков, избыточных абстракций.
- Имена переменных и функций отражают назначение.

## Градация замечаний

- **Blocker** — ошибочная логика, дыра в безопасности, отсутствие тестов на новое поведение.
- **Should-fix** — нарушение соглашения, плохая читаемость.
- **Nitpick** — стиль; можно не блокировать мерж.
