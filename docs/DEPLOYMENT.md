# Инструкция по релизу и деплою: dmc-268-api-t5

Документ описывает цикл сборки, доставки и безопасного управления секретами для сервиса API на целевом сервере Hetzner.

---

## 1. Архитектура и безопасность секретов

- **Модель изоляции секретов (Zero-Disk Env)**: Секреты (`LLM_API_KEY`, `DB_PASSWORD` и др.) **никогда не сохраняются на жесткий диск VPS**. 
- При деплое GitHub Actions передает переменные окружения напрямую в стандартный поток ввода Docker-демона:  
  `cat << 'EOF' | docker run --env-file - ...`
- Это исключает попадание секретов в файловую систему, историю shell и бэкапы диска сервера. Внутри приложения ключи доступны привычным способом через `process.env` (Node.js) или `os.environ` (Python).
- **Сетевая изоляция**: Контейнер работает в выделенной docker-сети `dmc-net`.

---

## 2. Необходимые секреты в GitHub Actions

В разделе **Settings -> Secrets and variables -> Actions** репозитория:

| Название секрета | Назначение |
| :--- | :--- |
| `VPS_DMC268_IP_T5` (Variable, не Secret) | IP-адрес сервера Hetzner |
| `VPS_DMC268_U` | SSH-пользователь |
| `VPS_DMC268_P` | Пароль пользователя SSH |
| `LLM_API_KEY` | Токен/ключ для работы с LLM |
| `DB_PASSWORD` | Пароль подключения к БД |

---

## 3. Выполнение DoD (Terraform)

Для первичной инициализации окружения и подъема базового контейнера используется workflow `.github/workflows/terraform-bootstrap.yml`:
1. Перейдите во вкладку **Actions** -> **Terraform Deploy to VPS**.
2. Нажмите **Run workflow**.
3. Terraform развернет базовый docker-контейнер и сеть `dmc-net` на выданном VPS.

---

## 4. Окружения и автодеплой

Один VPS, два окружения. Деплой запускается автоматически при пуше (после прохождения CI):

| Ветка | Environment | Контейнеры | Порт API | БД Postgres | Redis DB |
| :--- | :--- | :--- | :--- | :--- | :--- |
| `main` | `production` | `dmc-api-prod`, `dmc-worker-prod` | 8000 | `dmc_prod` | 0 |
| `develop` | `staging` | `dmc-api-staging`, `dmc-worker-staging` | 8100 | `dmc_staging` | 1 |

- Общие контейнеры `dmc-postgres` (создается деплоем, пароль `DB_PASSWORD` через STDIN) и `dmc-redis` (создает Terraform). Порты наружу не публикуются, доступны только в сети `dmc-net`.
- Worker (ARQ) запускается из того же образа командой `arq app.worker.WorkerSettings`.
- Тег образа: SHA коммита. При падении healthcheck выполняется автоматический откат на предыдущие контейнеры.
- Секреты можно задать отдельно на каждый Environment (**Settings -> Environments**), иначе используются репозиторные.
